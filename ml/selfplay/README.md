# Value-to-go (AlphaZero-style) for the Impact Optimizer

A **value network** for research. `V(abstract)` predicts the best target score an
abstract can **reach** after a few scientific extensions — its *achievable ceiling*,
not its current score. It reuses the `sciscore` framework wholesale: frozen SciBERT
embedding → a regression head. The training data is generated by **self-play**: the
Impact Optimizer already plays the game (propose → score → extend), so we run it over
many real abstracts and record the realized return.

```
   abstract ──propose──▶ extension ──score──▶ … ──▶ best score reached
      state                 action                    = value-to-go label
```

## Why

The optimizer's beam prunes by *current* score, so a path that scores low now but
would reach 92 in two steps gets killed early. `V` lets the beam rank by **reachable
ceiling** instead — the AlphaZero move (judge a position by its eventual outcome, not
the board eval now). It's also a standalone **"commercial headroom"** score:
`headroom = V(abstract) − current` → which papers are worth optimizing at all.

## The loop

### 1. Get roots (real abstracts)
```bash
mkdir -p ml/selfplay/data
bq query --use_legacy_sql=false --max_rows=2000 --format=csv \
  < ml/selfplay/sql/sample_abstracts.sql > ml/selfplay/data/abstracts.csv
```
Any CSV with an `abstract`/`text` column (or JSONL with that field) works.

### 2. Self-play → dataset (the one-time token spend)
```bash
cd "$(git rev-parse --show-toplevel)"
source ml/.venv/bin/activate
set -a; . ml/selfplay/.env; set +a          # AI_API_KEY, SCIENTIFIQ_API_KEY, …

# smoke test first — 3 roots, ~seconds, ~pennies:
python -m ml.selfplay.rollout --abstracts ml/selfplay/data/abstracts.csv \
  --out /tmp/vtg_smoke.csv --limit 3

# full run — commercial, depth 3, beam 3, 4 proposals/step, 1500 roots:
python -m ml.selfplay.rollout --abstracts ml/selfplay/data/abstracts.csv \
  --out ml/selfplay/data/valuetogo_commercial.csv \
  --target commercial --depth 3 --beam 3 --k 4 --limit 1500 --concurrency 8
```
Output is a `text,label` CSV (label = value-to-go in 0–1). Writes incrementally and
appends, so it's crash-safe and resumable. Proposer = **Haiku** (cheap); scoring is
free. Rough spend: ~`1 + beam·(depth−1)` proposer calls per root (≈7 at the defaults)
→ ~1500 roots ≈ 10k Haiku calls, one time. ~1500 roots yields ~8–12k labeled states —
the volume the other heads trained on.

### 3. Train the head (M5, minutes)
```bash
python -m ml.sciscore.cli train \
  --task ml/tasks/value_to_go_commercial.yaml \
  --data ml/selfplay/data/valuetogo_commercial.csv \
  --out ml/models/value_to_go_commercial
```
`value_to_go_commercial.yaml` is `kind: regression`, so the trainer fits a Ridge head
and reports **val_r2**. Embedding the ~10k abstracts is the only real compute.

### 4. Deploy (same Cloud Run service as the other tasks)
```bash
./ml/deploy_cloudrun.sh          # bakes every dir under ml/models/ into the image
```
The server (`/score`) serves any task folder under the model dir — no code change.

### 5. The app picks it up automatically
`lib/impactOptimizer.ts` calls `scoreText("value_to_go_commercial", abstract)`. Until
the model is deployed that returns `null` and the optimizer behaves exactly as today.
Once deployed:
- the beam ranks expansions by **reachable ceiling** (blended with current score), and
- each run reports the **headroom** of the pasted abstract.

## The self-improvement flywheel (later)
`v1` trains on trajectories from today's value-blind beam. Deploy it, and the beam's
rollouts get better → regenerate data → train `v2`. Policy and value bootstrap each
other, AlphaZero-style. One iteration already helps.

## Honest caveats
- **Per-target.** Reachability differs by dimension — start with `commercial`, prove
  it, then run the same loop with `--target scientific`, etc. (add a matching
  `value_to_go_<target>.yaml`).
- **It learns the *scorer's* landscape**, not ground truth — a search accelerator and
  headroom estimator, not a new truth measure. It inherits the scorers' biases.
- **Label noise.** MC returns depend on the proposer's luck; wider `--beam`/`--k` and
  more roots reduce variance, at more tokens.
- **Policy match.** The harness ports `proposeExtensionsAI` faithfully so the training
  distribution matches the app's action distribution. If you change the app's proposer
  prompt materially, regenerate.
